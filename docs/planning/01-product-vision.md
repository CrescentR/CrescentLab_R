# CrescentLab 产品愿景与边界

> 基线：2026-07-18  
> 产品事实来自当前首页文案、README、旧开发计划和已实现模块。未被代码或既有文档确认的规则集中记录在 `05-decisions-and-open-questions.md`。

## 1. 产品定位

### 1.1 产品是什么

CrescentLab 是一个自托管的个人技术实验室 CMS。它用一个公开站点承载文章、项目与实验记录，用一个管理后台完成内容维护和站点配置。

### 1.2 解决的问题

- 将分散的技术文章、项目状态和实验记录组织为可持续维护的公开档案。
- 让站点所有者不依赖第三方内容平台完成写作、发布和数据保留。
- 用同一内容系统复用文章、项目和媒体，而不是为每个项目重复搭建展示站。

### 1.3 服务对象

- 主要对象：维护个人技术实验室的站点管理员。
- 公开对象：阅读文章、项目与实验记录的访客。
- 待确认对象：是否提供真实“读者成员”、多作者和运营人员角色。

### 1.4 核心价值

核心价值不是模块数量，而是 **自托管、内容归属明确、发布路径清晰、技术项目与长文互相关联**。当前首页已经建立“正在构建—实验—项目—笔记”的表达，后端应围绕这条信息结构提供真实数据。

### 1.5 与通用博客/CMS 的差异

- 当前差异来自“个人 Labs 档案”信息结构，而非电商、社区或企业门户能力。
- 项目、实验记录与文章共同组成公开内容，不只是一条按日期排序的博客流。
- 采用 Go + Next.js 的自托管技术栈，并保留 SQLite 本地开发、PostgreSQL 部署的路径。

### 1.6 暂时不做

当前承诺范围不包含微服务、多租户 SaaS、主题商城、插件市场、社交关系、即时聊天、付费会员、复杂工作流引擎和多云存储全覆盖。PostgreSQL 已有相关表不等于产品已经承诺这些能力。

## 2. 用户角色

| 角色 | 当前状态与定义 | 使用目标 | 可访问功能 | 禁止操作 | 主要路径 |
| --- | --- | --- | --- | --- | --- |
| 访客 | 已确认；无需登录的公开访问者 | 阅读文章、项目和实验记录 | 首页、已发布文章列表与详情；未来经确认的评论入口 | 访问后台、读取草稿、修改站点数据 | 首页 → 内容列表 → 内容详情 |
| 站点管理员 | 已确认目标角色；当前仅前端原型 | 写作、发布、配置和维护站点 | 登录后访问全部已授权后台功能 | 未登录时调用任何 `/api/admin/*`；越过服务端权限校验 | 登录 → 后台 → 编辑/配置 → 发布 → 前台验证 |
| 读者成员 | 待确认；当前只有 persona 原型 | 评论、订阅和维护个人资料 | 只有产品确认后才进入承诺范围 | 后台管理、修改他人数据 | 登录 → 阅读 → 互动/订阅 → 个人资料 |
| 内容作者/编辑 | 待确认；数据库有用户组与权限表，但无运行代码 | 管理自己或被授权的内容 | 取决于 Q-018 多作者决策 | 未授权发布、删除或修改他人内容 | 后台内容列表 → 编辑 → 提交/发布 |
| 运维人员 | 规划角色，不代表独立账号类型 | 部署、备份、恢复和观察运行状态 | 运行环境、健康检查、日志、备份 | 通过业务 UI 读取不必要的敏感数据 | 部署 → 健康检查 → 监控 → 备份/恢复 |
| 第三方系统 | 未来可选 | 存储、邮件或搜索集成 | 仅访问明确授权的集成接口 | 访问后台通用 API 和明文密钥 | 配置 → 鉴权 → 调用 → 审计 |

## 3. 核心用户流程

### 3.1 访客阅读

1. 访客进入 `/`。
2. 系统加载公开品牌设置与已发布内容；加载失败时保留可读的页面结构并显示明确错误状态。
3. 访客从首页文章/项目/实验入口进入内容列表或详情。
4. 详情页只展示 `published` 且未软删除的内容。
5. 内容不存在、未发布或已删除时返回统一 404 页面，不泄露其真实状态。

### 3.2 管理员登录与进入后台

1. 管理员进入登录页并提交凭据。
2. 后端验证用户状态、密码和管理员权限。
3. 成功后建立可撤销的登录态；失败时返回不泄露账号是否存在的错误。
4. 前端加载当前身份并显示被授权的后台入口。
5. 未登录或无权限访问后台时，页面引导登录或显示 403；服务端同时拒绝请求。

### 3.3 文章发布闭环

1. 管理员进入后台文章列表。
2. 创建草稿或打开已有文章。
3. 编辑标题、slug、摘要、正文、封面和状态等已确认字段。
4. 保存草稿；系统持久化并返回更新时间。
5. 管理员预览后发布；系统设置 `published_at`。
6. 首页和公开文章详情读取同一条已发布数据。
7. 管理员可以归档或软删除；公开端立即停止展示。

### 3.4 站点设置生效

1. 管理员进入 `/admin/settings`。
2. 系统读取 `site/branding` 设置。
3. 管理员修改并保存。
4. 后端原子写入设置；前端刷新公开设置缓存。
5. 首页和后台在下一次加载时展示新品牌资源。

## 4. 产品目标

| 时间范围 | 目标 | 可判断完成条件 |
| --- | --- | --- |
| 短期 | 建立安全、可重复运行的管理基线 | 干净环境 test/vet/build 通过；本地数据库按文档初始化；真实管理员登录；所有 `/api/admin/*` 未认证返回 401；健康检查可区分存活和数据库就绪 |
| 中期 | 完成文章发布闭环 | 管理员可创建、保存、预览、发布、归档、软删除；访客可从首页进入已发布文章详情；核心流程有 PostgreSQL 集成测试与 E2E |
| 中期 | 让品牌设置与内容组织真实生效 | branding 保存后被公开端读取；分类/标签和本地媒体满足文章组织需要；未接入模块不再展示误导性成功操作 |
| 长期 | 达到可自托管运营状态 | 生产配置无默认密钥；有备份/恢复、回滚、监控和告警；权限与审计规则通过验收；连续发布版本具备回归记录 |

## 5. 产品边界

### 5.1 当前版本必须做

- 可重复构建、数据库初始化/版本检查和基础 CI。
- 管理员真实登录、退出、刷新与后台服务端保护。
- 文章管理列表、编辑、状态流转、公开列表和详情。
- Markdown/HTML 安全渲染边界。
- 品牌设置读取与生效。
- 最小健康检查、日志关联、错误契约和部署说明。

### 5.2 可以延后

- 本地媒体库、分类、标签。
- 评论审核、真实读者账号、细粒度用户组权限。
- 文章历史版本、定时发布、搜索、RSS/Sitemap。
- 高级统计和邮件订阅。

### 5.3 暂时不做

- 多云存储适配全覆盖。
- 主题安装/商城与二进制插件运行。
- 音乐、相册、友链的完整后台闭环。
- Redis、消息队列、外部搜索服务。

### 5.4 不建议做

- 在主链路未闭环前同时实现 PostgreSQL 71 张表对应模块。
- 为当前单站点规模拆分微服务或引入复杂事件基础设施。
- 同时支持 Markdown、Tiptap JSON 和任意 HTML 三套同等编辑主路径。
- 用前端角色状态、隐藏按钮或默认回退替代后端权限校验。

### 5.5 未来可扩展

阶段 4 稳定后，可依据真实需求从主题、插件、相册、友链、通知、订阅、搜索、统计和多云存储中逐项立项。每项必须先说明用户、频率、数据生命周期和验收指标，再进入路线图。
