# CrescentLab 分期开发路线图

> 路线图只承诺四个阶段。扩展评审池不等于待开发清单。阶段编号与 `phases/`、`04-master-task-list.md` 保持一致。

## 1. 总览

| 阶段 | 阶段名称 | 核心目标 | 主要功能 | 前置条件 |
| --- | --- | --- | --- | --- |
| 01 | 可重复构建与安全门禁 | 让项目可在干净环境安全启动并保护后台 | 依赖锁定、SQLite 初始化、健康检查、登录/退出/刷新、JWT 中间件、统一错误、最小 CI | 决定账号模型、管理员初始化、Token 存放与测试目录规则 |
| 02 | 文章发布闭环 | 完成“登录—写作—发布—公开阅读” | 后台文章列表、编辑/保存/发布、预览、公开列表与详情、安全渲染、核心 E2E | 阶段 01 完成；确定正文主格式、slug 和发布权限规则 |
| 03 | 媒体与内容组织 | 让文章资产、分类标签和品牌设置可维护 | 本地媒体上传/选择、分类标签、branding 生效、孤立数据治理 | 阶段 02 完成；确定文件限制、删除规则和 URL 策略 |
| 04 | 互动与生产运维 | 建立可运营、可恢复的自托管版本 | 评论与审核、用户/权限最小集、审计、备份恢复、监控告警、发布回滚 | 阶段 03 完成；确认读者账号、多作者和评论政策 |

## 2. 阶段 01：可重复构建与安全门禁

### 背景

当前管理 API 无鉴权，Go 依赖校验阻塞 test/vet，本地 SQLite 是空文件，且没有健康检查。继续扩展业务会放大安全和验证成本。

### 目标与范围

- 修复依赖和包管理器漂移，建立干净环境质量门禁。
- 明确数据库初始化与 schema 就绪检查。
- 实现真实登录态并保护全部 `/api/admin/*`。
- 建立统一错误、请求限制、日志关联、liveness/readiness。
- 建立最小 CI 和部署基线文档。

### 非本期范围

文章管理 UI、媒体、评论、主题、插件、Redis、消息队列和自动生产迁移。

### 交付成果与验收

| 交付物 | 验收条件 |
| --- | --- |
| 构建基线 | 干净工作区执行 Go test/vet/build 与前端 lint/typecheck/build 全部通过 |
| 数据库基线 | 新环境按文档初始化 SQLite/PostgreSQL；readiness 能识别缺表和数据库不可达 |
| 认证与授权 | 登录成功建立有效身份；退出/撤销后不可继续使用；全部管理 API 未认证 401、无权限 403 |
| HTTP 基线 | 统一错误码；内部错误不回传；超时、body 上限和 request_id 可测试 |
| CI | 每次提交自动执行上述静态检查和测试 |

### 风险与后续关系

最大风险是账号/Token 规则未确认导致返工。阶段 01 是后续所有管理能力的硬前置；未完成不得部署到公网。

## 3. 阶段 02：文章发布闭环

### 背景

文章 API 已实现，但首页、后台 dashboard 和编辑器均使用静态数据，产品核心价值尚未交付。

### 目标与范围

- 后台文章列表：状态筛选、搜索、分页、创建入口和明确空/错状态。
- 编辑器：加载、创建、更新、保存草稿、发布、归档、软删除、未保存提示。
- 公开文章列表与详情；首页使用真实已发布内容。
- 确定正文单一事实源并安全渲染。
- 补认证集成、PostgreSQL 集成和核心 E2E。

### 非本期范围

富媒体库、评论、多人审核、定时发布、文章历史恢复、全文搜索和复杂 SEO。

### 交付成果与验收

| 交付物 | 验收条件 |
| --- | --- |
| 后台页面 | 管理员能从列表创建/编辑文章；所有按钮对应真实操作 |
| API | 现有文章 API 经鉴权和错误契约扩展；不破坏公开读接口 |
| 公开页面 | 只有 published 且未删除内容可访问；首页可进入详情 |
| 数据 | SQLite/PostgreSQL 对文章主路径表现一致，状态与时间字段符合规则 |
| 测试 | 登录→建草稿→发布→公开读取→归档/删除的 E2E 通过 |

### 风险与后续关系

正文格式、HTML 净化、并发编辑和 slug 变更规则必须在开发前确认。完成后才能定义媒体引用、分类标签和评论对象。

## 4. 阶段 03：媒体与内容组织

### 背景

当前文章只能填写外部 `cover_url`，PostgreSQL 文件模型远超实际能力，branding 保存后也不生效。本期只交付内容发布真正需要的最小资产能力。

### 目标与范围

- 本地存储策略、受控上传、媒体列表、选择和软删除。
- 文章分类与标签的管理、选择和公开展示。
- 公开品牌设置读取、缓存失效和首页/后台应用。
- 文件引用与删除约束、孤立文件识别、双库数据一致性测试。

### 非本期范围

分片上传、多云存储、OAuth 存储、视频转码、内容去重、公开直链配额和外部搜索。

### 交付成果与验收

| 交付物 | 验收条件 |
| --- | --- |
| 媒体库 | 管理员上传允许类型文件并在文章中选择；越权、超限、伪造类型被拒绝 |
| 内容组织 | 分类/标签可维护并被文章使用；删除被引用对象按已确认规则处理 |
| 品牌设置 | 保存后公开端和后台在规定时机展示新资源；失败可观察且不伪装成功 |
| 测试 | 上传安全、引用一致性、分类标签和设置生效 E2E 通过 |

### 风险与后续关系

文件路径、大小、类型和保留规则会影响备份与恢复；本期数据生命周期是阶段 04 运维方案的输入。

## 5. 阶段 04：互动与生产运维

### 背景

项目要成为可长期自托管产品，必须同时具备互动治理和可恢复运维，而不是只增加页面。

### 目标与范围

- 根据已确认政策实现评论提交、展示、审核和软删除。
- 根据已确认账号模型实现最小用户/用户组权限管理。
- 对登录、发布、删除、设置、评论审核记录审计事件。
- 建立生产配置、备份/恢复、健康监控、告警、发布和回滚流程。
- 完成安全回归、故障演练和正式使用文档。

### 非本期范围

评论点赞、附件、地理分析、邮件通知、主题/插件市场和多租户。

### 交付成果与验收

| 交付物 | 验收条件 |
| --- | --- |
| 评论 | 公开展示只含 approved；审核动作受权限保护并有审计记录 |
| 用户权限 | UI 展示与服务端授权一致；不能操作越权数据 |
| 运维 | PostgreSQL 备份可恢复到隔离环境；发布可回滚；关键故障触发告警 |
| 安全 | 密钥无默认值、日志脱敏、登录/评论限流和依赖扫描通过 |
| 完成定义 | 生产检查表、恢复演练、核心回归与文档全部通过 |

### 风险与后续关系

评论合规、真实成员和多作者规则未确认时，本期对应功能保持阻塞。完成本期后，项目才可评估为“可用版本/正式产品”。

## 6. 扩展评审池

以下能力只保留为未来立项方向：相册、友链、主题、插件、通知、订阅、音乐、高级统计、全文搜索、多云存储、定时任务。进入路线图前必须证明使用者、频率、与核心内容流的关系、数据生命周期和维护成本。
