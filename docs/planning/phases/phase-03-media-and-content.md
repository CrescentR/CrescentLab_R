# 第 03 期：媒体与内容组织

> 路线图基线：`docs/planning/02-roadmap.md` 阶段 03
> 前置阶段：阶段 02 完成（文章发布闭环可用）
> 前置决策：见 `05-decisions-and-open-questions.md` 中 Q-010 ~ Q-013

---

## 1. 阶段概述

### 1.1 本期解决什么问题

1. 文章封面和正文图片只能填写外部 URL，没有本地上传能力。
2. 品牌设置（siteLogoUrl 等）保存后，前端 `siteBranding` 仍是静态常量，不读取已保存值。
3. 文章没有分类和标签管理能力，列表筛选和公开展示缺少内容组织维度。
4. PostgreSQL 中文件、存储策略等 71 张表远超实际能力，形成认知负担。

### 1.2 为什么安排在这一期

文章发布闭环完成后，管理员需要上传图片到文章和封面、用分类和标签组织内容、让品牌设置真正生效。这些是内容维护的基本需求，但不属于核心发布链路，因此排在阶段 02 之后。

### 1.3 本期完成后的产品状态

- 管理员可在媒体库上传文件（图片），并在文章编辑器中选择作为封面或正文图片。
- 管理员可管理文章分类和标签，文章可关联分类和标签。
- 品牌设置保存后，首页和后台在下次加载时展示新品牌资源。
- 访客可在首页看到分类筛选，在文章详情看到分类和标签。

### 1.4 本期对整个项目的价值

让内容系统从"能发布文章"升级为"能组织和美化内容"。品牌设置生效让站点真正属于管理员。文件上传为阶段 04 的评论图片和未来媒体功能提供基础。

## 5. 详细功能需求

### 5.1 本地媒体上传

#### 5.1.1 功能目的

让管理员将图片上传到服务器本地存储，用于文章封面和正文。

#### 5.1.2 使用角色

站点管理员。

#### 5.1.3 功能入口

- 前端页面：`/admin/media`（从占位页改为真实页面）
- HTTP 接口：`POST /api/admin/media/upload`

#### 5.1.4 页面展示内容

媒体库页面：

| 区域 | 内容 |
| --- | --- |
| 页面标题 | "媒体库" |
| 上传区 | 拖拽上传区 + "选择文件"按钮 |
| 文件列表 | 网格视图（缩略图 + 文件名 + 大小 + 上传时间） |
| 搜索 | 按文件名搜索 |
| 操作 | 点击文件查看详情、复制 URL、删除 |

#### 5.1.5 操作流程

1. 管理员进入 `/admin/media`。
2. 拖拽或选择图片文件。
3. 前端发送 `POST /api/admin/media/upload`（multipart/form-data）。
4. 后端校验文件类型、大小。
5. 后端保存文件到 `data/uploads/` 目录，按年月组织子目录。
6. 后端在 `files` 表中创建记录。
7. 返回文件信息（含公开访问 URL）。
8. 前端刷新文件列表。

#### 5.1.6 业务规则

- 允许的文件类型：jpg、jpeg、png、gif、webp、svg。
- 单文件大小上限：10MB（本期硬编码，后续可配置）。
- 文件存储路径：`data/uploads/YYYY/MM/<uuid>.<ext>`。
- 公开访问 URL：`/uploads/YYYY/MM/<uuid>.<ext>`（由 Go 静态文件服务提供）。
- 文件名在列表中显示原始名，存储使用 UUID 防冲突。
- 上传需要认证 + 管理员。
- 软删除：`deleted_at` 标记后不从列表展示，但文件不物理删除（本期不实现物理清理）。

#### 5.1.7 状态设计

| 状态 | 含义 |
| --- | --- |
| active | 文件可用 |
| deleted | 已软删除 |

#### 5.1.8 数据要求

需要在 SQLite 中补建 `files` 表（PostgreSQL 已有）：

| 字段 | 含义 | 类型 | 必填 | 默认值 |
| --- | --- | --- | --- | --- |
| id | 主键 | INTEGER/BIGINT | 是 | 自增 |
| name | 原始文件名 | TEXT | 是 | — |
| uri | 存储路径 | TEXT | 是 | — |
| public_url | 公开访问 URL | TEXT | 是 | — |
| mime_type | MIME 类型 | TEXT | 是 | — |
| size | 文件大小（字节） | BIGINT | 是 | — |
| storage_type | 存储类型 | TEXT | 是 | "local" |
| owner_id | 上传者 ID | INTEGER/BIGINT | 否 | NULL |
| created_at | 创建时间 | DATETIME | 是 | CURRENT_TIMESTAMP |
| updated_at | 更新时间 | DATETIME | 是 | CURRENT_TIMESTAMP |
| deleted_at | 软删除时间 | DATETIME | 否 | NULL |

#### 5.1.9 权限要求

- 上传、列表、删除：需认证 + 管理员。
- 公开访问 `/uploads/*`：不需要认证。

#### 5.1.10 异常情况

| 场景 | 前端处理 | 后端处理 |
| --- | --- | --- |
| 文件类型不允许 | 前端校验拦截 | 返回 400 |
| 文件超过 10MB | 前端校验拦截 | 返回 413 |
| 磁盘空间不足 | 显示"上传失败" | 返回 507 |
| 上传中断 | 显示"上传失败，请重试" | — |
| 同名文件 | 不冲突（UUID） | — |

#### 5.1.11 验收标准

- Given 已登录管理员，When 上传 2MB 的 jpg 文件，Then 文件出现在列表中且可通过 URL 访问。
- Given 未登录用户，When 尝试上传，Then 返回 401。
- Given 15MB 文件，When 尝试上传，Then 返回 413。
- Given .exe 文件，When 尝试上传，Then 返回 400。
- Given 已上传文件，When 点击删除并确认，Then 文件从列表消失。

### 5.2 编辑器媒体选择

#### 5.2.1 功能目的

让管理员在编辑文章时从媒体库选择图片作为封面或插入正文。

#### 5.2.2 使用角色

站点管理员。

#### 5.2.3 功能入口

- 文章编辑器中的"封面"字段旁增加"从媒体库选择"按钮
- 编辑器正文区域的"插入图片"按钮

#### 5.2.4 页面展示内容

媒体选择弹窗：

| 区域 | 内容 |
| --- | --- |
| 弹窗标题 | "选择图片" |
| 搜索 | 按文件名搜索 |
| 网格 | 缩略图网格，点击选中 |
| 确认按钮 | 选中后点击"确认" |

#### 5.2.5 操作流程

1. 管理员在编辑器中点击"从媒体库选择"。
2. 弹窗展示已上传图片。
3. 管理员点击选中一张图片。
4. 点击"确认"。
5. 弹窗关闭，封面 URL 或正文图片 Markdown 填入编辑器。

#### 5.2.6 业务规则

- 只展示图片类型文件（mime_type 以 `image/` 开头）。
- 选中后填入的是 `public_url`。
- 正文图片插入为 Markdown 格式 `![文件名](public_url)`。

#### 5.2.7 状态设计

| 状态 | 含义 |
| --- | --- |
| browsing | 浏览媒体库 |
| selected | 已选中一张图片 |
| confirmed | 已确认选择 |

#### 5.2.8 数据要求

无新增数据。读取 `files` 表。

#### 5.2.9 权限要求

- 需认证 + 管理员。

#### 5.2.10 异常情况

| 场景 | 处理 |
| --- | --- |
| 无已上传图片 | 弹窗显示空状态 + "去上传"按钮 |
| 网络异常 | 弹窗显示"加载失败" |

#### 5.2.11 验收标准

- Given 编辑器中，When 点击"从媒体库选择"，Then 弹窗展示已上传图片。
- Given 弹窗中选中图片，When 点击"确认"，Then 封面 URL 或正文图片被填入。
- Given 无已上传图片，When 打开弹窗，Then 显示空状态。

### 5.3 分类管理

#### 5.3.1 功能目的

让管理员创建和维护文章分类，文章可关联一个分类，访客可按分类筛选。

#### 5.3.2 使用角色

站点管理员（管理），访客（筛选）。

#### 5.3.3 功能入口

- 后台页面：`/admin/categories`（新增）或在文章列表中内联管理
- HTTP 接口：`/api/admin/categories`（CRUD）

#### 5.3.4 页面展示内容

分类管理页面（可简化为设置页内的一个区域或独立页面）：

| 区域 | 内容 |
| --- | --- |
| 页面标题 | "分类管理" |
| 新建表单 | 名称、slug、描述 |
| 分类列表 | 名称、slug、文章数、操作（编辑、删除） |

#### 5.3.5 操作流程

1. 管理员进入分类管理。
2. 创建分类：输入名称、slug 和描述。
3. 编辑分类：修改名称或描述。
4. 删除分类：弹出确认，删除后关联该分类的文章 category_id 置为 NULL。
5. 在文章编辑器中，分类字段为下拉选择，列出所有分类。

#### 5.3.6 业务规则

- 分类 slug 唯一。
- 分类名称非空。
- 删除分类时，文章的 `category_id` 置为 NULL（不阻止删除）。
- 文章计数（`article_count`）在文章发布/取消发布时更新。
- 分类有 `sort_order` 字段，默认按 sort_order 升序排列。

#### 5.3.7 状态设计

无状态流转。分类是静态组织维度。

#### 5.3.8 数据要求

使用现有 `post_categories` 表（SQLite 和 PostgreSQL 均已有）。无新增字段。

#### 5.3.9 权限要求

- 管理操作：需认证 + 管理员。
- 公开读取分类列表：公开。

#### 5.3.10 异常情况

| 场景 | 处理 |
| --- | --- |
| slug 重复 | 返回 409 |
| 删除被引用的分类 | 允许删除，文章 category_id 置 NULL |
| 名称为空 | 返回 400 |

#### 5.3.11 验收标准

- Given 管理员，When 创建分类"工程笔记"（slug: engineering-notes），Then 分类出现在列表中。
- Given 已有分类的文章，When 删除该分类，Then 文章的 category_id 变为 NULL。
- Given 文章编辑器，When 打开分类下拉，Then 列出所有分类。
- Given 访客，When 访问 `/api/articles?category=engineering-notes`，Then 只返回该分类的文章。

### 5.4 标签管理

#### 5.4.1 功能目的

让管理员为文章添加标签，文章可关联多个标签，标签可作为内容发现维度。

#### 5.4.2 使用角色

站点管理员（管理），访客（查看）。

#### 5.4.3 功能入口

- 文章编辑器中的"标签"字段
- HTTP 接口：`/api/admin/tags`（CRUD）、`/api/admin/articles/:id/tags`（关联）

#### 5.4.4 页面展示内容

编辑器中的标签区域：

| 区域 | 内容 |
| --- | --- |
| 标签输入 | 文本输入框，输入后回车创建标签 |
| 已选标签 | Badge 列表，点击 × 移除 |
| 建议标签 | 已有标签下拉（可选） |

#### 5.4.5 操作流程

1. 管理员在编辑器中输入标签名。
2. 回车后前端检查标签是否已存在（按 slug）。
3. 如不存在，创建标签后关联到文章。
4. 如已存在，直接关联。
5. 点击标签上的 × 移除关联。
6. 保存文章时提交标签关联变更。

#### 5.4.6 业务规则

- 标签 slug 唯一，由名称自动生成（中文用拼音或保留原文，**待确认** Q-012）。
- 一篇文章最多关联 10 个标签。
- 标签名称非空，1~30 字符。
- 删除标签时，文章标签关联一并删除。
- 标签在文章详情页公开展示。

#### 5.4.7 状态设计

无状态。

#### 5.4.8 数据要求

需要在 SQLite 中补建 `post_tags` 和 `article_tags` 表（PostgreSQL 已有）：

`post_tags` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| name | TEXT | 标签名 |
| slug | TEXT | 唯一 slug |

`article_tags` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| article_id | INTEGER | 文章 ID |
| tag_id | INTEGER | 标签 ID |
| PRIMARY KEY | — | (article_id, tag_id) |

#### 5.4.9 权限要求

- 管理操作：需认证 + 管理员。
- 公开读取标签：公开。

#### 5.4.10 异常情况

| 场景 | 处理 |
| --- | --- |
| 标签名重复（slug 相同） | 复用已有标签，不创建新标签 |
| 超过 10 个标签 | 返回 400 |
| 标签名为空 | 前端校验拦截 |

#### 5.4.11 验收标准

- Given 编辑器，When 输入"Go"并回车，Then 标签"Go"被关联到文章。
- Given 文章已有 10 个标签，When 尝试添加第 11 个，Then 返回 400。
- Given 文章详情页，When 查看，Then 显示所有关联标签。
- Given 删除标签关联，When 保存，Then 标签不再出现在详情页。

### 5.5 品牌设置生效

#### 5.5.1 功能目的

让保存的品牌设置（siteLogoUrl、adminLogoUrl、defaultAvatarUrl、heroImageUrl、faviconUrl）被公开端和后台读取并展示，替换前端静态常量 `siteBranding`。

#### 5.5.2 使用角色

站点管理员（保存），访客（查看），系统（应用）。

#### 5.5.3 功能入口

- HTTP 接口：`GET /api/public/settings`（新增公开读取接口）
- 前端：`frontend/src/lib/site-settings.ts`（修改为从 API 加载）

#### 5.5.4 页面展示内容

无直接页面。品牌资源体现在：

- 首页：logo、hero 图片、favicon
- 后台：admin logo、默认头像
- 浏览器标签页：favicon

#### 5.5.5 操作流程

1. 管理员在 `/admin/settings` 修改品牌设置并保存。
2. 后端写入 `settings` 表。
3. 前端首页/后台启动时调用 `GET /api/public/settings?group_key=branding`。
4. 后端返回 `is_public = true` 的品牌设置。
5. 前端用返回值替换静态常量 `siteBranding`。
6. 页面展示新的 logo、hero 图片等。

#### 5.5.6 业务规则

- 公开接口只返回 `is_public = true` 的设置。
- 品牌设置默认 `is_public = true`（已有逻辑）。
- 前端在应用初始化时加载一次品牌设置，缓存在内存中。
- 管理员保存后，前端需要刷新页面才能看到变化（本期不实现实时推送）。

#### 5.5.7 状态设计

| 状态 | 含义 |
| --- | --- |
| loading | 正在加载品牌设置 |
| loaded | 已加载，使用 API 返回值 |
| fallback | 加载失败，使用静态默认值 |

#### 5.5.8 数据要求

无新增数据。使用现有 `settings` 表。

#### 5.5.9 权限要求

- 公开读取：`GET /api/public/settings` 不需要认证。
- 管理保存：`PUT /api/admin/settings` 需认证 + 管理员（阶段 01 已保护）。

#### 5.5.10 异常情况

| 场景 | 前端处理 | 后端处理 |
| --- | --- | --- |
| 公开接口失败 | 使用静态默认值 | 返回 500 |
| 品牌设置为空 | 使用静态默认值 | 返回空数组 |
| URL 无效 | 不展示该资源 | — |

#### 5.5.11 验收标准

- Given 管理员保存新的 siteLogoUrl，When 刷新首页，Then 首页 logo 更新。
- Given 管理员保存新的 heroImageUrl，When 刷新首页，Then hero 图片更新。
- Given 访客（未登录），When 访问 `GET /api/public/settings`，Then 返回 `is_public=true` 的设置。
- Given 公开接口失败，When 首页加载，Then 使用静态默认值且不崩溃。

### 5.6 公开分类筛选

#### 5.6.1 功能目的

让访客在首页或分类页按分类筛选文章。

#### 5.6.2 使用角色

访客。

#### 5.6.3 功能入口

- 前端页面：首页文章区域增加分类筛选标签
- 或新增 `/categories` 页面

#### 5.6.4 页面展示内容

首页文章区域增加分类筛选条：

| 区域 | 内容 |
| --- | --- |
| 分类标签 | "全部" + 各分类名称，点击切换 |
| 文章列表 | 按选中分类筛选 |

#### 5.6.5 操作流程

1. 访客进入首页。
2. 文章区域上方显示分类标签条。
3. 点击"全部"显示所有已发布文章。
4. 点击某个分类名，筛选该分类的文章。
5. 文章列表更新。

#### 5.6.6 业务规则

- 分类标签按 `sort_order` 排序。
- 只展示有已发布文章的分类（article_count > 0）。
- 筛选使用 `GET /api/articles?category=<slug>`。

#### 5.6.7 状态设计

无。

#### 5.6.8 数据要求

无新增数据。

#### 5.6.9 权限要求

- 公开访问。

#### 5.6.10 异常情况

| 场景 | 处理 |
| --- | --- |
| 无分类 | 不显示分类筛选条 |
| 分类下无文章 | 不显示该分类标签 |

#### 5.6.11 验收标准

- Given 有分类且有已发布文章，When 访问首页，Then 显示分类筛选条。
- Given 点击分类"工程笔记"，When 文章列表更新，Then 只显示该分类文章。
- Given 无分类，When 访问首页，Then 不显示分类筛选条。

## 9. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 文件上传 p99 < 2s（10MB 以内）；媒体列表 p99 < 200ms |
| 安全 | 文件类型白名单校验；上传路径不可遍历；公开设置不返回 `is_encrypted` 的值 |
| 可用性 | 媒体库有上传进度、空状态和错误状态 |
| 响应速度 | 品牌设置加载不阻塞首屏渲染 |
| 浏览器兼容 | Chrome 120+、Firefox 120+、Safari 17+ |
| 数据一致性 | 分类删除后文章 category_id 在 SQLite 和 PostgreSQL 中表现一致 |
| 日志 | 文件上传、分类/标签 CRUD 写日志，关联 user_id |
| 测试要求 | 上传安全测试；分类标签 CRUD 测试；品牌设置生效 E2E |
