# 项目完整审阅与分期规划

> 日期：2026-07-18  
> 范围：产品、架构、工程质量、测试、部署与长期开发计划  
> 限制：本次只新增规划文档，不修改业务代码

## 目标

基于当前工作树中的代码、配置、数据库脚本、页面、测试、Git 历史和既有文档，建立一套可追溯、可验收、可分阶段执行的产品与技术计划。

## 验收标准

- `docs/planning/00-project-audit.md` 记录现状、能力、问题、证据和阶段判断。
- `docs/planning/01-product-vision.md` 明确定位、角色、流程、目标和边界。
- `docs/planning/02-roadmap.md` 给出有前置关系和完成定义的阶段路线图。
- `docs/planning/phases/` 中每个阶段都有独立、可执行的需求文档。
- `docs/planning/03-technical-plan.md` 覆盖架构、数据、接口、安全、测试和运维。
- `docs/planning/04-master-task-list.md` 汇总全部已承诺阶段任务。
- `docs/planning/05-decisions-and-open-questions.md` 集中记录决策和待确认事项。
- 文档中的当前事实可定位到仓库文件；无法确认的业务规则统一标为“待确认”或“建议”。
