# 内容管理与媒体中心产品需求文档（PRD）

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 内容管理与媒体中心 |
| 文档版本 | V1.0 |
| 文档性质 | 从成熟 CMS 实现反推的技术无关 PRD |
| 适用产品 | CMS、企业官网、博客、知识库、文档站、内容社区 |
| 目标读者 | 产品经理、设计师、前后端开发、测试、项目负责人 |

## 2. 产品背景

内容型产品通常会逐步遇到以下问题：

- 页面、文章、知识文档分别开发，编辑、发布、历史版本等能力重复建设；
- 正文修改后直接影响线上内容，缺乏安全的草稿机制；
- 图片散落在编辑器、封面、图库等不同入口，无法统一管理；
- 文件存储与具体云服务绑定，后续迁移困难；
- 用户误关闭页面或多人编辑时，内容容易丢失或被覆盖；
- 删除附件后仍有内容引用，或者删除记录后物理文件残留；
- 发布、缩略图生成、外部文件转存等耗时操作缺少明确的处理状态。

本产品要提供一套统一的内容创作、版本管理、发布和媒体管理能力，并允许不同业务形态在同一底座上扩展。

## 3. 产品目标

### 3.1 核心目标

1. 用户能够创建、编辑、预览、发布、下线和回收内容。
2. 草稿内容与线上内容严格隔离，编辑不影响已发布版本。
3. 所有图片、音频、视频和文件进入统一媒体中心。
4. 正文图片、封面和图片集均复用同一套媒体选择能力。
5. 内容支持历史版本、版本恢复和编辑冲突保护。
6. 媒体存储方式可切换或扩展，而不改变上层使用方式。
7. 耗时任务具有明确状态，失败可见、可恢复、可重试。

### 3.2 非目标

V1 不包含：

- 实时多人协同编辑；
- 复杂工作流编排；
- 数字资产版权交易；
- 专业图片后期处理；
- 无限层级的网盘式目录；
- 跨站点内容同步；
- AI 写作和 AI 图片生成。

## 4. 用户角色

| 角色 | 主要诉求 |
|---|---|
| 超级管理员 | 配置存储、权限、全站内容和媒体策略 |
| 内容管理员 | 管理所有文章、页面、文档、附件和发布状态 |
| 编辑者 | 创建和编辑自己有权限的内容，管理可用附件 |
| 投稿者 | 创建草稿、提交内容，不能直接管理全站配置 |
| 访客 | 浏览已发布且允许公开访问的内容 |
| 扩展提供方 | 接入新的编辑器、媒体来源或文件存储服务 |

## 5. 产品范围

产品分为五个业务域：

1. 内容管理；
2. 编辑器；
3. 版本与发布；
4. 媒体中心；
5. 前台内容访问。

### 5.1 内容类型

系统至少支持：

| 内容类型 | 使用场景 | 特有能力 |
|---|---|---|
| 文章 | 博客、新闻、动态 | 分类、标签、归档、内容流 |
| 独立页面 | 关于、协议、友链、落地页 | 固定访问路径、独立模板 |
| 文档 | 帮助中心、知识库、产品文档 | V1 可复用页面能力，后续增加目录树和文档集 |

三类内容应复用正文、版本、发布、封面、可见性、评论开关和回收站能力。

## 6. 核心产品概念

### 6.1 内容条目

内容条目保存标题、路径、作者、封面、可见性、发布设置等业务信息，不直接承担历史正文存储。

### 6.2 草稿版本

用户当前正在编辑的正文版本。草稿变化不得影响访客正在查看的线上版本。

### 6.3 发布版本

当前对外展示的正文版本。发布操作本质上是确认某个草稿版本成为线上版本。

### 6.4 历史版本

每次形成有效保存节点后产生的可追溯版本。历史版本可以查看、比较和恢复。

### 6.5 附件

上传或转存到系统中的图片、音频、视频、压缩包、文档等文件。

### 6.6 图片集

图片集是正文中的一种内容块，由多张附件图片及其布局设置组成，不是独立媒体仓库。

### 6.7 存储策略

描述附件存储位置和规则的配置，例如“默认本地存储”“生产对象存储”“私有文件存储”。

## 7. 总体业务关系

```text
内容条目
  ├── 内容类型：文章 / 页面 / 文档
  ├── 当前草稿版本
  ├── 当前发布版本
  ├── 历史版本
  └── 封面附件

正文
  ├── 文本、标题、列表、引用等
  ├── 单张图片
  ├── 文件链接
  └── 图片集
        └── 多个附件或外部图片

媒体中心
  ├── 附件
  ├── 分组
  ├── 标签
  ├── 缩略图
  └── 存储策略
```

## 8. 功能需求

## 8.1 内容列表

### 8.1.1 列表展示

内容列表应展示：

- 标题；
- 内容类型；
- 作者和贡献者；
- 发布状态；
- 可见性；
- 发布时间；
- 最后修改时间；
- 封面；
- 是否存在未发布修改；
- 异常或处理中状态。

### 8.1.2 搜索与筛选

用户可按以下条件筛选：

- 关键词；
- 作者或贡献者；
- 草稿、已发布、待发布、发布失败；
- 公开、内部、私有；
- 分类和标签，仅文章适用；
- 创建时间、发布时间、更新时间；
- 正序或倒序。

筛选、分页和排序条件应反映在页面 URL 中，刷新页面或分享链接后仍可恢复。

### 8.1.3 批量操作

支持：

- 批量移入回收站；
- 批量恢复；
- 批量永久删除；
- 批量修改可见性；
- 批量发布或下线，是否在 V1 开放由权限和风险决定。

### 8.1.4 验收标准

- 列表可分页，翻页后条件不丢失；
- 搜索和筛选可组合使用；
- 无权查看的内容不得出现在结果中；
- 处理中内容展示明确状态，不伪装成操作已完成；
- 批量操作需二次确认，并反馈成功数、失败数和失败原因。

## 8.2 内容创建与编辑

### 8.2.1 新建内容

新建时用户可设置：

- 内容类型；
- 标题；
- 正文；
- 路径标识；
- 封面；
- 摘要；
- 可见性；
- 评论开关；
- 发布时间；
- 模板；
- 分类、标签，仅文章适用。

标题和路径可由系统生成默认值，但发布前必须满足唯一性和合法性要求。

### 8.2.2 编辑器

编辑器应支持：

- 标题、段落、加粗、斜体、删除线；
- 有序列表、无序列表、任务列表；
- 引用、代码块、分割线；
- 链接；
- 单图、音频、视频、附件；
- 图片集；
- 撤销和重做；
- 快捷键保存；
- 从媒体中心选择附件；
- 直接上传附件；
- 粘贴外部图片后的转存提示。

不同编辑器可输出不同原始格式。系统必须记录正文格式，确保再次打开时可选择兼容的编辑器。

### 8.2.3 保存

用户可主动保存。系统还应提供编辑保护：

- 输入停止一段时间后保存本地恢复副本；
- 页面失焦时保存本地恢复副本；
- 离开或关闭页面前保存本地恢复副本；
- 再次打开时，如果服务器版本未变化，提示恢复；
- 如果服务器版本已变化，不得自动用本地副本覆盖。

本地恢复副本、服务器草稿和正式历史版本是三种不同概念，界面文案不得混淆。

### 8.2.4 编辑冲突

保存时必须携带用户开始编辑时的版本信息。

若服务器版本已变化：

- 不得静默覆盖；
- 应提示内容已被其他会话更新；
- 至少允许用户保留自己的内容副本；
- 推荐提供“查看最新版本”“另存为新草稿”“人工合并”。

V1 可先实现“拒绝覆盖 + 保留本地副本”，不强制实现可视化合并。

## 8.3 内容设置

### 8.3.1 基础设置

- 标题；
- 访问路径；
- 封面；
- 摘要；
- 作者；
- 模板；
- 评论开关。

### 8.3.2 可见性

| 类型 | 规则 |
|---|---|
| 公开 | 任何访客可访问 |
| 内部 | 仅已登录且满足内部访问条件的用户可访问 |
| 私有 | 仅作者和被授权人员可访问 |

可见性检查必须同时作用于列表、详情、搜索、预览资源和公开接口。

### 8.3.3 摘要

用户可选择：

- 自动摘要：从发布正文提取；
- 手工摘要：使用用户输入内容。

摘要应基于发布版本生成，不能泄露未发布草稿。

### 8.3.4 访问路径

- 同一站点和同类内容下必须唯一；
- 修改路径后是否保留旧路径跳转，由产品配置决定；
- 不允许与系统保留路径冲突；
- 页面使用固定路径；
- 文章可支持包含日期、分类等变量的路径规则。

## 8.4 发布管理

### 8.4.1 状态模型

建议状态：

| 状态 | 含义 |
|---|---|
| 草稿 | 尚未发布 |
| 待发布 | 已提交发布请求，系统处理中 |
| 定时发布 | 等待设定时间 |
| 已发布 | 存在可对外访问的发布版本 |
| 有未发布修改 | 已发布，但当前草稿领先于线上版本 |
| 发布失败 | 发布校验或处理失败 |
| 已下线 | 曾发布，当前不再公开 |
| 回收站 | 逻辑删除，不在正常列表和前台出现 |

“是否想发布”和“系统是否发布成功”必须分开记录，不能只使用一个布尔字段。

### 8.4.2 发布

发布前校验：

- 标题非空；
- 路径合法且唯一；
- 正文存在；
- 当前草稿版本存在；
- 可见性合法；
- 定时发布时间合法；
- 引用的必需资源可访问；
- 用户有发布权限。

发布成功后：

- 当前草稿成为发布版本；
- 生成或更新公开访问地址；
- 更新发布时间和状态；
- 触发搜索索引、缓存刷新等后续任务；
- 历史版本中保留发布节点。

### 8.4.3 修改已发布内容

编辑已发布内容时：

- 访客继续看到原发布版本；
- 后台显示“有未发布修改”；
- 再次发布后才替换线上版本；
- 下线不删除草稿和历史版本。

### 8.4.4 定时发布

- 用户可设置未来发布时间；
- 到达时间后系统自动执行发布；
- 时区必须明确；
- 发布失败需记录原因并通知有权限用户；
- 用户可在执行前取消或修改。

### 8.4.5 预览

预览应展示当前草稿，而不是发布版本。

- 预览链接需鉴权或使用短时效令牌；
- 私有内容不得通过猜测链接访问；
- 预览应尽量使用真实主题和页面布局。

## 8.5 历史版本

### 8.5.1 版本列表

每个版本展示：

- 创建时间；
- 创建人；
- 贡献者；
- 版本说明，可选；
- 是否为当前草稿；
- 是否为当前发布版本；
- 是否为发布节点。

### 8.5.2 查看与比较

- 可查看任意历史版本；
- 可比较两个版本；
- 文本内容至少支持新增、删除和修改标识；
- 非文本块应展示结构变化摘要。

### 8.5.3 恢复

恢复历史版本时：

- 不直接删除恢复点之后的历史；
- 用目标版本内容创建新的当前草稿；
- 不自动影响线上发布版本；
- 用户需要再次发布才更新线上内容；
- 当前发布版本不可被直接删除。

### 8.5.4 清理

- 第一个基础版本不得删除；
- 当前草稿和当前发布版本不得删除；
- 可设置版本保留数量或保留时间；
- 清理任务不得破坏任一可读版本。

## 8.6 回收站

### 8.6.1 移入回收站

- 内容立即从正常列表和前台隐藏；
- 正文、版本、评论等关联数据暂时保留；
- 可恢复；
- 记录删除人和删除时间。

### 8.6.2 永久删除

- 必须二次确认；
- 删除所有正文版本；
- 删除或解绑评论、统计、搜索索引；
- 默认不删除正文引用的附件，因为附件可能被其他内容复用；
- 失败时保留可继续清理的状态，不能出现无记录但资源残留的静默失败。

## 8.7 媒体中心

### 8.7.1 附件列表

附件应展示：

- 预览图或文件类型图标；
- 显示名称；
- 原文件名，可选；
- MIME 类型；
- 文件大小；
- 上传者；
- 所属分组；
- 存储策略；
- 上传时间；
- 当前处理状态。

### 8.7.2 视图

- 列表视图；
- 网格视图；
- 用户选择应被记住。

### 8.7.3 搜索与筛选

支持：

- 关键词；
- 图片、音频、视频、普通文件；
- MIME 类型；
- 上传者；
- 分组；
- 存储策略；
- 上传时间；
- 文件大小；
- 排序。

### 8.7.4 上传

支持：

- 点击选择文件；
- 拖拽上传；
- 多文件上传；
- 上传进度；
- 取消上传；
- 失败重试；
- 选择目标分组；
- 选择存储策略，权限允许时；
- 上传完成后立即返回可选择的附件。

### 8.7.5 上传校验

系统必须校验：

- 最大文件大小；
- 允许和禁止的文件类型；
- 文件真实类型，不能只信扩展名；
- 文件名合法性；
- 重名处理策略；
- 用户剩余配额；
- 存储策略是否可用。

### 8.7.6 URL 转存

用户可输入外部 URL，将文件保存到媒体中心。

规则：

- 必须防止访问内网和本机地址；
- 限制响应大小和下载时间；
- 限制跳转次数；
- 跳转后的每个地址都要重新进行安全检查；
- 支持从响应头或 URL 推断文件名；
- 转存后生成普通附件，后续使用方式与上传附件一致。

### 8.7.7 附件详情

用户可：

- 预览；
- 复制公开链接；
- 修改显示名称；
- 修改分组；
- 编辑标签；
- 查看媒体类型、大小、尺寸和上传者；
- 查看不同尺寸缩略图；
- 下载；
- 删除；
- 查看引用关系，在系统支持引用跟踪时。

### 8.7.8 批量操作

- 批量删除；
- 批量移动分组；
- 批量添加或移除标签；
- 批量修改存储位置属于高风险能力，V1 不要求。

## 8.8 媒体分组与标签

### 8.8.1 分组

- 新建、重命名、删除分组；
- 将附件移动到分组；
- 支持“未分组”；
- 删除分组时附件默认变为未分组，不删除文件；
- V1 仅支持单层分组。

### 8.8.2 标签

- 一个附件可有多个标签；
- 标签用于搜索和筛选；
- 标签不改变物理存储路径。

## 8.9 存储策略

### 8.9.1 目标

上层业务只依赖统一附件能力，不感知文件实际存储在本地、S3、OSS 或其他服务。

### 8.9.2 管理能力

管理员可：

- 新建存储策略；
- 选择存储驱动；
- 填写驱动配置；
- 测试连接；
- 设置为默认策略；
- 设置适用用户或业务端；
- 停用策略；
- 查看策略使用中的附件数量。

### 8.9.3 规则

- 已被附件使用的策略不可直接删除；
- 敏感配置必须加密存储且不可明文回显；
- 更改策略配置不得自动改变已有附件归属；
- 存储驱动应统一提供上传、删除、公开链接、临时分享链接和缩略图能力；
- 某驱动不支持的能力应明确降级，不得伪造成功。

## 8.10 缩略图

图片上传后可生成多个尺寸的缩略图。

需求：

- 原图始终保留；
- 列表、网格、编辑器和前台根据场景选择尺寸；
- 生成失败不应导致原附件上传失败，但需显示处理状态；
- 支持关闭缩略图；
- 缩略图删除应与原附件生命周期一致；
- 外部存储可返回其自身图片处理 URL；
- 不支持缩略图的文件使用文件类型图标。

## 8.11 附件选择器

所有需要文件的地方共用附件选择器，包括：

- 内容封面；
- 正文图片；
- 图片集；
- 音视频；
- 文件下载链接；
- 其他表单附件字段。

选择器支持：

- 单选和多选；
- 最少、最多选择数量；
- 允许的 MIME 类型；
- 搜索、筛选、分页；
- 直接上传；
- 已选状态；
- 切换媒体来源。

选择器应允许接入第三方来源，例如云盘、图库或企业资产库。第三方来源统一返回最小资源信息：

- 唯一标识；
- 显示名称；
- 可用 URL；
- 缩略图；
- 媒体类型；
- 文件大小，可选。

## 8.12 图片集

### 8.12.1 创建

用户可从编辑器工具栏或命令菜单插入图片集，并通过以下方式添加图片：

- 直接上传多张图片；
- 从媒体中心多选；
- 从已接入的第三方资源源选择。

### 8.12.2 编辑

支持：

- 拖动排序；
- 删除单张图片；
- 继续添加图片；
- 设置每行图片数量；
- 设置自适应比例或统一方形；
- 设置图片间距；
- 使用适当缩略图减少编辑器加载量。

### 8.12.3 数据规则

每个图片项至少保存：

- 图片 URL；
- 原始宽高比；
- 替代文本，建议；
- 附件 ID，建议。

如果只保存 URL，实现较简单，但无法可靠完成附件引用追踪、删除保护和链接迁移。产品若明确需要这些能力，应同时保存附件 ID。

### 8.12.4 验收标准

- 图片顺序保存后不变；
- 切换布局不会丢图；
- 图片未加载出宽高时不会破坏布局；
- 编辑器使用缩略图，前台可使用合适的展示资源；
- 删除图片集中的图片不等于删除媒体中心附件；
- 无上传权限的用户仍可在有查看权限时选择已有附件。

## 8.13 前台内容访问

### 8.13.1 页面访问

- 已发布页面通过唯一访问路径打开；
- 使用页面指定模板，未指定时使用默认模板；
- 页面被下线、回收或改为无权限可见后，原公开地址不可继续返回正文；
- 展示内容必须来自发布版本。

### 8.13.2 文章访问

- 支持按文章路径访问；
- 支持分类、标签、作者、归档列表；
- 只展示符合发布和可见性条件的文章；
- 列表摘要来自发布版本。

### 8.13.3 搜索

- 只索引发布版本；
- 草稿和私有内容不得进入公共搜索；
- 发布、下线、永久删除后触发索引更新；
- 索引处理失败不影响内容数据，但需可观察和重试。

## 8.14 权限

建议权限粒度：

| 权限 | 说明 |
|---|---|
| 内容查看 | 查看有权范围内的内容 |
| 内容创建 | 创建草稿 |
| 内容编辑本人 | 编辑自己的内容 |
| 内容编辑全部 | 编辑任意内容 |
| 内容发布 | 发布、下线和定时发布 |
| 内容删除 | 移入回收站 |
| 内容永久删除 | 永久清理 |
| 附件查看 | 浏览和选择附件 |
| 附件上传 | 上传或转存附件 |
| 附件管理本人 | 修改、删除自己的附件 |
| 附件管理全部 | 修改、删除任意附件 |
| 存储策略管理 | 配置存储驱动和策略 |

权限必须在服务端校验，前端隐藏按钮只能改善体验，不能作为安全措施。

## 9. 关键业务规则

1. 内容内部 ID 永久稳定，不能使用可变 slug 作为主键。
2. 草稿版本和发布版本必须分离。
3. 发布版本不存在时，内容不能进入已发布状态。
4. 恢复历史版本只改变草稿，不直接改变线上内容。
5. 回收内容立即停止前台访问，但保留可恢复数据。
6. 永久删除内容默认不级联删除附件。
7. 删除附件必须确保物理文件和派生资源得到清理。
8. 附件删除过程中应显示处理中，失败后可重试。
9. 图片集删除图片只解除正文引用，不删除附件。
10. 同一附件可被多个内容、封面或图片集复用。
11. 自动摘要、搜索索引和公开页面只读取发布版本。
12. 所有耗时或最终一致操作必须提供处理中、成功、失败状态。

## 10. 关键流程

### 10.1 新建并发布

```text
新建内容
  → 编辑标题和正文
  → 本地恢复副本持续更新
  → 保存服务器草稿
  → 完善发布设置
  → 发起发布
  → 系统校验
  → 草稿版本设为发布版本
  → 更新公开地址、摘要、搜索和缓存
  → 显示发布成功
```

### 10.2 修改已发布内容

```text
打开已发布内容
  → 加载当前草稿
  → 修改并保存
  → 状态变为“有未发布修改”
  → 访客继续看旧发布版本
  → 再次发布
  → 新草稿替换发布版本
```

### 10.3 恢复历史版本

```text
打开历史版本
  → 查看或比较
  → 点击恢复
  → 二次确认
  → 用旧内容创建新的草稿版本
  → 返回编辑器
  → 用户决定是否发布
```

### 10.4 上传并插入图片集

```text
插入图片集
  → 打开附件选择器
  → 上传或选择多张图片
  → 返回统一资源信息
  → 生成图片集内容块
  → 调整顺序、每行数量、布局和间距
  → 保存到正文草稿
```

### 10.5 删除附件

```text
请求删除
  → 检查权限和引用
  → 标记删除中
  → 删除原文件
  → 删除缩略图
  → 清理附件记录
  → 成功

任一步失败
  → 保留失败状态
  → 展示原因
  → 管理员重试
```

## 11. 异常与边界场景

| 场景 | 期望行为 |
|---|---|
| 保存时服务器版本已变化 | 拒绝静默覆盖，保留用户本地内容 |
| 发布版本对应正文丢失 | 发布失败，线上旧版本不受影响 |
| 上传成功但附件记录创建失败 | 自动清理孤立物理文件或进入补偿任务 |
| 附件记录删除但存储服务失败 | 保持删除中/删除失败，可重试 |
| 缩略图生成失败 | 原文件可用，展示默认预览并允许重试 |
| 外部 URL 指向内网 | 拒绝转存 |
| 存储驱动不可用 | 上传失败并显示明确原因 |
| 用户离开未保存页面 | 本地保存恢复副本，下次提示恢复 |
| slug 与系统路由冲突 | 发布前阻止并提示 |
| 图片集引用附件被删除 | 使用保留 URL 降级或显示资源失效状态 |
| 定时发布时权限已变化 | 按任务创建时授权策略或执行时重新校验，产品需统一选择 |

## 12. 非功能需求

### 12.1 性能

- 内容列表首屏查询建议在 1 秒内返回；
- 常规保存建议在 2 秒内给出明确结果；
- 附件列表必须分页；
- 图片网格使用缩略图和懒加载；
- 大文件上传不得整体读入应用内存；
- 历史版本数量增加后，读取当前版本的性能不应线性下降。

### 12.2 安全

- 服务端权限校验；
- 上传大小和类型限制；
- 文件名净化和路径穿越防护；
- URL 转存防 SSRF；
- 私有文件使用鉴权或短时效链接；
- 存储密钥加密；
- 正文渲染进行 XSS 防护；
- 预览链接不可永久公开；
- 删除和发布等重要操作记录审计日志。

### 12.3 可靠性

- 内容保存使用乐观并发控制；
- 发布、转存、删除、缩略图和索引任务支持幂等；
- 异步任务可重试；
- 失败任务可查询；
- 数据记录与物理文件之间有补偿机制；
- 不得因派生任务失败丢失正文或原附件。

### 12.4 可扩展性

- 新内容类型可复用版本和发布能力；
- 新编辑器可声明支持的正文格式；
- 新存储驱动可实现统一媒体接口；
- 新媒体选择来源可接入统一选择器；
- 前台主题可读取统一发布内容模型。

## 15. MVP 验收清单

### 内容

- [ ] 可创建页面和文章。
- [ ] 已发布内容继续编辑时，前台内容不变化。
- [ ] 再次发布后前台切换到新版本。
- [ ] 可下线且不丢失草稿和历史。
- [ ] 可移入回收站并恢复。
- [ ] 可查看并恢复历史版本。
- [ ] 恢复历史版本不会自动覆盖线上版本。
- [ ] 并发保存不会静默覆盖。
- [ ] 意外离开后可恢复本地内容。

### 媒体

- [ ] 可多文件上传并显示进度。
- [ ] 上传类型和大小受到限制。
- [ ] 可用列表和网格浏览。
- [ ] 可搜索并按媒体类型、分组筛选。
- [ ] 可创建分组并移动附件。
- [ ] 可从统一选择器选择封面和正文图片。

### 图片集

- [ ] 可上传或选择多张图片。
- [ ] 可拖动排序。
- [ ] 可设置每行数量、布局和间距。

- [ ] 删除图片集中的图片不会删除媒体中心附件。

## 16. 待产品决策

以下问题会显著影响设计，需要项目启动时确认：

1. 产品只服务单站点，还是多租户、多站点？
2. “文档”只是另一种内容类型，还是需要文档集和树状目录？
3. 是否需要发布审批，还是有发布权限即可直接发布？
4. 是否需要定时发布？
5. 私有附件是 V1 必需，还是只有内容访问权限？
6. 图片集是否必须保存附件 ID 并阻止被引用附件删除？
7. 删除附件时，是强制阻止、提示后删除，还是允许降级为失效图片？
8. 历史版本按每次手动保存生成，还是按时间间隔聚合？
9. 是否允许编辑者选择存储策略？
10. slug 修改后是否自动建立旧地址跳转？
11. 评论是本项目范围还是外部系统？
12. 搜索是 MVP 必需还是后续能力？

## 17. 产品设计原则

1. **草稿永不直接污染线上版本。**
2. **用户内容优先于自动处理结果，派生任务失败不能造成正文丢失。**
3. **媒体只管理一次，到处复用。**
4. **图片集是内容表现形式，不是第二套附件系统。**
5. **业务概念独立于具体编辑器、后端语言和存储厂商。**
6. **异步过程必须对用户可见，失败必须可恢复。**
7. **先保证完整版本正确，再考虑差量存储优化。**
