# 项目：从「发布中心」到「长期线索」

## 目标

站点理念是「记录进展 · 整理方法 · 分享成果」。项目应当是一条长期线索：月相说明它在哪个阶段，目标／边界／现在说明它是什么，而关联的长文、札记与进展记录说明它是怎么走到这里的。本次让后台围绕这条线索来编辑，前台详情页把过程完整展示出来。

## 已确认的决定（2026-10-29）

1. **进展归入项目**：`builds` 保留为一条条带日期的「进展」记录，必须关联项目；在项目编辑页内新增、编辑、删除。独立的「构建中」后台入口移除，`/admin/builds` 跳转到项目。
2. **路线进度百分比**：后台隐藏、前台不展示，数据库列保留不动。「下一步」取该项目最新一条公开进展的 `next_step`。
3. **发布状态只管可见性**：项目状态只有草稿／公开（`draft`／`published`）。项目是否结束只看月相下弦 + 退出类型（归档／放弃）。旧 `archived` 状态通过手动 SQL 转为 `published` + 下弦。
4. **后台视觉**：沿用后台现有设计语言（Panel、Badge、Field、Button 与 CSS 变量），只整理项目页的层级、表单控件和列表。

## 数据与接口

- 项目 `Validate`：`status` 仅允许空／`draft`／`published`；公开项目必须有月相。下弦必须有退出类型和原因（不变）。
- 公开项目列表与详情只返回 `published`。
- 进展 `CreateInput`：`project_id` 必填；公开进展必须写 `latest_progress`（不再要求 `one_liner`）；新增可选 `progressed_at`，留空时新建取当前时间、编辑保留原值（修复每次编辑都把日期改成当天的问题）。
- 进展列表支持 `project_id` 过滤（公开与后台）。
- 新增 `GET /api/admin/projects/related?id=`：返回关联的长文、札记摘要（含草稿与私有，用于后台）。
- 手动 SQL：`database/{sqlite,postgres}/2026-10-29-projects.sql`，把 `archived` 项目转为公开 + 下弦；升级前备份后人工执行一次。

## 界面

- 后台列表：按月相分组（研究／构建／上线／下弦／阶段待补充），每行显示月相、名称、「现在」、草稿标记、最近更新；编辑与删除按钮常驻。
- 后台编辑页四个分区：档案（身份 + 月相四段选择器 + 目标／边界／现在 + 下弦退出原因 + 链接）、README 正文、过程（进展 CRUD + 关联长文／札记只读列表）、部署版本（不变）。
- 前台详情页：月相轨迹、目标／边界／现在／下一步、按时间倒序的完整过程时间线（长文、札记、进展），之后是 README 正文。
- 前台列表页去掉进度条；样式细节随详情页统一。

## 升级注意

- 先备份，再执行对应数据库的 `2026-10-29-projects.sql`。
- 已有但未关联项目的进展记录会出现在后台项目列表顶部的「未归属的进展」区，选择项目即可归入（`POST /api/admin/builds/assign` 只改 `project_id`，不重新校验旧内容），也可直接删除；归入后在该项目的「过程」里编辑。这类记录在归属前仍会在公开笔记时间线中显示。
- 经 SQL 转换后若下弦项目没有退出原因，下次保存时后台会要求补写。
