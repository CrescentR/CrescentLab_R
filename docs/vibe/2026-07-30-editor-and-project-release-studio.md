# 编辑器与项目发布工作台改造

> 日期：2026-07-30  
> 状态：已实现

## 目标

将文章与项目从“基础富文本表单”升级为统一的内容创作与发布系统：

1. 文章和项目共用同一套 TipTap 编辑能力，以保留 TipTap 语义结构的净化 HTML 保存内容，不再用正则把 HTML 反向转换为 Markdown。
2. 编辑器支持标题层级、文本样式、链接、图片、任务列表、表格、代码块、分隔线、快捷保存、字数统计、专注写作和预览。
3. 项目编辑页必须读取完整详情，避免保存列表投影时清空正文。
4. 项目可上传单文件 HTML 或包含 `index.html` 的 ZIP 静态站点。
5. 项目产物按不可变版本保存，支持预览、发布、查看历史与回滚。
6. 上传内容不注入主站 DOM；通过独立产物路由和沙箱 iframe 展示，并设置 CSP、安全响应头和 MIME 白名单。

## 范围与取舍

### 本次实现

- 统一富文本编辑器内核和内容数据结构。
- 文章与项目草稿保存、预览和发布体验。
- 项目 HTML/ZIP 上传、校验、解包、版本列表、发布和回滚。
- 本地文件存储，目录为 `data/project-artifacts/`。
- SQLite 与 PostgreSQL 所需表结构。
- 后端单元/集成测试、前端类型检查、构建和 Docker 主链路验证。

### 本次不实现

- 在服务器执行用户上传的构建脚本。
- 云对象存储、多租户、多人实时协同和可视化三方合并。
- 对任意后端程序、容器镜像或动态服务进行托管。
- 将上传 HTML 的 Cookie、localStorage 或同源权限开放给主站。

## 数据与安全设计

- `project_artifacts` 保存产物元数据；文件内容按随机 `public_id` 落在独立目录。
- 每次上传生成新版本，不覆盖旧版本。
- 发布或回滚只改变项目当前发布产物指针，不修改历史产物。
- ZIP 解包拒绝绝对路径、`..` 路径穿越、符号链接、超量文件和超限解压大小。
- 仅允许静态网页常见文件类型；入口必须是根目录 `index.html`。
- 产物响应附带严格 CSP、`X-Content-Type-Options: nosniff` 和禁止索引响应头。
- 管理端 iframe 使用 `sandbox="allow-scripts allow-forms allow-modals allow-popups"`，不授予 `allow-same-origin`。

- [x] 编辑已有项目会先读取详情，正文不会因列表数据不完整而被清空。
- [x] 编辑器提供表格、任务列表、代码块、图片、链接、统计和快捷保存能力。
- [x] HTML 文件上传后能在隔离预览区运行。
- [x] 合法 ZIP 上传后能正确加载相对 CSS、JS 和图片资源。
- [x] 路径穿越 ZIP、缺少入口文件、超限产物会被明确拒绝。
- [x] 产物列表可区分草稿版本与当前发布版本。
- [x] 可发布指定版本，并可回滚到任意历史版本。
- [x] 文章与项目写接口均使用 POST。
- [x] 相关 Go 测试、前端类型检查和生产构建通过。
- [ ] Docker 环境下验证登录、文章编辑、项目编辑、上传、预览、发布和回滚主链路。
